# チケット精緻化 (Ticket Refinement)

起票後のチケットを、**命題の実現内容まで展開**し、**分割判定できる厚さ**まで充足する。完了条件の補完だけではない。

**常時読むのは本ファイルだけ。** 本文は目録の条件に合うファイルだけ開く。`sections/` をまとめて読まない。

## 目録

| 開く条件 | 読むファイル |
|----------|----------------|
| 命題が薄い・未展開 | `sections/proposition.md` |
| 成果物あり、または画面・操作・UIあり | `sections/quality-axes.md` |
| description 更新／充足・テスト合格ライン | `sections/sufficiency.md` |
| 骨組みが無い、または例・テンプレが欲しい | `sections/template-examples.md` |
| プロジェクト誤り防止・get/update 例 | `sections/ops.md` |

充足済みなら **追加ファイルはゼロ** で呼び出し元へ戻ってよい。

## 概要

### 自動起動

1. 命題のリッチ化（薄いなら `proposition.md`）
2. 品質観点を条件へ（必要なら `quality-axes.md`）
3. 充足チェック（`sufficiency.md`）
4. 欠けがあれば更新（テンプレは `template-examples.md`）
5. ジャーナル `精緻化: {要約}`（充足済みなら「更新なし」）
6. 実装前に `ticket-split` へ（許可待ちしない）

DoD 不能／外部情報必須のみ質問最大3つ。充足スキップでも **split 判定はする**。分割済みの子なら通常「分割不要」。

### 精緻化する／しない

| する | しない（更新スキップ。判定はする） |
|------|--------|
| 命題未展開、実現の内訳が無い | 充足チェックをすべて満たす |
| 品質観点が条件／テストに落ちていない | 子が既に充足（漏れ拾い） |
| DoD だけ／検証不能／範囲不明 | 質問・設計相談のみ |
| `#N 精緻化` 明示 | |

**DoD 検証可能だけではスキップしない。命題未展開・品質観点未反映でもスキップしない。**  
ゴールは長文化ではない。欄埋めだけでは不合格。

### 最小フロー

1. `get`（例は `ops.md`）
2. 命題 → 品質観点 → 充足チェック → 欠けだけ更新
3. ジャーナル

品質4観点の詳細・禁止・落とし方は `quality-axes.md`。精緻化後チェックは `sufficiency.md`。
