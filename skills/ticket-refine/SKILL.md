# チケット精緻化 (Ticket Refinement)

起票後のチケットを、**分割判定できる厚さ**まで充足する。完了条件の補完だけではない。

## 自動起動（ticket-driven から）

`ticket-driven` の着手・実装フローでは、ユーザー確認なしで本スキルを実行する。DoD が検証可能でも、要件が薄ければ更新する。

1. 充足チェック（下記）で欠けを特定する
2. 欠けがあれば最小テンプレで description を更新する
3. ジャーナル `精緻化: {要約}`（更新しなくても判定したら 1 行。充足済みなら「更新なし」）
4. 呼び出し元へ戻し、**実装の前に `ticket-split`（機能構成単位）へ進む**（許可待ちしない）

まだ DoD が書けない／外部情報が必須な場合だけ質問を最大3つ。推測で埋められる範囲は埋めて進める。

充足済み（更新スキップ）でも、呼び出し元は **同じタイミングで `ticket-split` を判定**する。本スキルの更新をスキップしたからといって分割判定までスキップしない。作業対象が **分割済みの子** なら、split は通常「分割不要」で戻る。

## 精緻化する／しない

| する（自動 or 明示） | しない（更新スキップ。判定はする） |
|------|--------|
| 着手時に要件が分割・実装に足りない（DoD だけある薄いチケットを含む） | 充足チェックをすべて満たす（説明が短くても可） |
| 完了条件が検証不能（「良くする」「対応する」だけ） | 分割で作られた子が、すでに充足ラインを満たす（**漏れ拾い**。足りれば更新しない） |
| 範囲が不明で影響ファイルの見当がつかない | 質問・設計相談のみ |
| ユーザーが `#N 精緻化` と明示 | |

**DoD が検証可能であることだけではスキップしない。**

精緻化のゴールは長文化ではない。**分割できる要件の厚さと、検証可能な完了条件**を作ること。

精緻化の直後（または充足済み判定の直後）は、必ず `ticket-split` で **機能構成単位**に分解してから作業する。無理に1枚の親へ実装を詰め込まない。単一機能構成なら split 側が「分割不要」と判定する。

## 登録先プロジェクト（誤り防止）

精緻化対象チケットの **所属プロジェクトを変えたり、別プロジェクトへ新規を切ったりしない**。

- アプリ固有（例: brave-search-mcp）→ そのプロジェクトのチケットを更新
- スキル／運用ルール本体（ticket-driven）→ `{your-redmine-project}`
- ワークスペースのカレントだけでプロジェクトを推測しない。`get` の `project` を見る

## 最小フロー（デフォルト）

1. `get`（`include: ["journals"]`）
2. 充足チェックで欠けを列挙する
3. 欠けだけ足す。骨組みが無いときだけ最小テンプレで差し替える
4. ジャーナル: `精緻化: {要約}`

リモート未確保で実装不能なら、コメントに「リポジトリ未作成」→ Feedback 等で保留（毎回必須検査ではない。実装チケットで remote が要るときだけ）。

### get / update

取得（`redmine_issues`）:

```json
{ "action": "get", "issue_id": "{ID}", "include": ["journals"] }
```

説明更新 + ノート（`redmine_api_request`。`redmine_issues` に update/add_note は無い）:

```json
{
  "method": "PUT",
  "path": "/issues/{ID}.json",
  "body": {
    "issue": {
      "description": "{精緻化内容}",
      "notes": "精緻化: {要約}"
    }
  }
}
```

## 充足チェック（分割前）

次をすべて満たせば更新スキップ。1つでも欠けたら埋める。見出し名は一致しなくてよい（同等の内容があれば可）。

| 項目 | 見るポイント |
|------|----------------|
| 背景・目的 | 何がどうなるか一言で言えるか |
| 範囲 | やる／やらないが分かるか（完了条件から自明なら本文に無くても可） |
| 完了条件 | コマンド／差分で判定できるか |
| 影響範囲 | 触るファイル・モジュールの見当 |
| テスト範囲 | 下記の合格ラインを満たすか（見出しがあるだけでは不可） |
| 失敗時・境界 | 振る舞いが自明でないとき、期待が書いてあるか |
| 依存 | 他チケット・外部サービス待ちがあるか（無ければ「なし」で可） |

失敗時・境界は、バグの再現手順や「〜しない」が完了条件に既にあるなら追加しない。

非機能・エッジケースは **分割と実装に必要なときだけ**足す。毎回フル項目を埋めない。

## テスト範囲の合格ライン

正本はここ。着手後に別の計画を書き足さない（漏れ拾いは `ticket-driven`）。

必須:

- **完了条件との対応**: 各完了条件について、どう検証するかを書く。1コマンドで複数をまとめてよいが、どれを見るかは書く
- **手段の区別**: 各項目を 自動 / 手動 / 目視 のいずれかにする
- **失敗経路**: 範囲に失敗時・境界があるなら、その経路を1つ入れる

不合格（これだけでは足りない）:

- DoD の言い換えだけでは不合格
- `cargo test` が通る、だけ（完了条件の言い換え）
- 対象・手順・合格の見出しだけ埋まって、中身が完了条件のコピー
- 網羅表・カバレッジ目標（要求しない）

例外: ドキュメントのみ・読み取り調査のみは「目視確認」で計画扱いしてよい。

分割後は **子が自分の完了条件に対応した計画** を持つ。親の薄いテスト範囲をコピーしない。

## 完了条件（必須）

悪い例（禁止に近い）:

- 品質を高める / 適切に対応する / 堅牢にする
- 必要に応じてテストする

良い例:

- `cargo test` が通る
- `src/brave_search.rs` に 429 リトライ（最大3回）が入る
- README の「テスト / CI」にモック手順が1段落ある
- `scripts/ci.sh` が exit 0

書けない完了条件は、質問を **最大3つ** に絞ってユーザーへ返す（質問リストの量産はしない）。

質問を出す場合の観点（必要なものだけ）:

- 入力／出力の形
- 失敗時の期待（エラーメッセージ、リトライ有無）
- テストの有無（単体 / 無視付き結合）

## 最小テンプレ（デフォルトで使う）

```
## 背景
（1〜3文）

## 目的
（このチケットで達成すること・1〜2文）

## 範囲
- やる: …
- やらない: …

## 完了条件
- [ ] 検証可能な条件1
- [ ] 検証可能な条件2

## 影響範囲
- 変更予定: path/to/file（分かれば）

## テスト範囲
- 完了条件1: 自動 — コマンド …（見るもの）
- 完了条件2: 手動または目視 — …
- 失敗経路: （範囲に失敗時があるときだけ）

## 実装方針
（任意・分かれば箇条書き1〜3）
```

失敗時・境界が自明でないときだけ、範囲の下に「失敗時」を足す。

## 精緻化後チェック

- [ ] 充足チェックをすべて満たす
- [ ] テスト範囲が合格ラインを満たす（DoD の言い換えだけではない）
- [ ] 完了条件がすべて検証可能
- [ ] 次工程の `ticket-split`（機能構成単位）へ渡せる状態である
- [ ] 正しいプロジェクトのチケットを更新した（または更新スキップした）
- [ ] ジャーナルに精緻化要約がある

## 例

### 前（DoD だけある薄いチケット）

```
## 完了条件
- [ ] src/brave_search.rs にリトライが入る
- [ ] cargo test が通る
```

DoD は検証可能でも、範囲・失敗時・テストが無いので **スキップしない**。

### 後

```
## 背景
Brave API の一時的な 429/5xx でツール呼び出しが即失敗する。

## 目的
一時障害時に限って安全にリトライする。

## 範囲
- やる: 429 / 5xx / 接続エラーのリトライ
- やらない: 401/403 のリトライ、無制限リトライ

## 完了条件
- [ ] 429 と 5xx と接続エラーのみリトライ（401/403 はしない）
- [ ] 最大3回・指数バックオフ
- [ ] ユニットまたはモックテストでリトライ経路を1つ以上検証
- [ ] `cargo test` が通る

## 影響範囲
- 変更: src/brave_search.rs

## テスト範囲
- 429/5xx/接続エラーをリトライ: 自動 — `cargo test retry`（モックでリトライ経路）
- 401/403 はリトライしない: 自動 — 同上（リトライしない経路が1つ）
- 最大3回・指数バックオフ: 自動 — 同上（回数・間隔のアサーション）
- `cargo test` 全体: 自動 — `cargo test`
```
