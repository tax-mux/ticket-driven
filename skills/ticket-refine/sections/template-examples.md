# 最小テンプレと例

## 最小テンプレ（デフォルトで使う）

```
## 背景
（1〜3文）

## 目的
（命題の言い直し・達成状態 1〜2文）

## 実現内容
- （内訳を箇条書き。分割の種になる粒度）

## 範囲
- やる: …
- やらない: …

## 完了条件
- [ ] 検証可能な条件1
- [ ] 検証可能な条件2
- [ ] （該当する品質観点を検証可能な形で 0〜数個）

## 影響範囲
- 変更予定: path/to/file（分かれば）

## テスト範囲
- 完了条件1: 自動 — コマンド …（見るもの）
- 完了条件2: 手動または目視 — …
- 失敗経路: （範囲に失敗時があるときだけ）

## 実装方針
（任意・分かれば箇条書き1〜3）
```

失敗時・境界が自明でないときだけ、範囲の下に「失敗時」を足す。  
`## 品質観点` 見出しは作らない（条件へ落とす）。

## 例

### 前（DoD だけある薄いチケット）

```
## 完了条件
- [ ] src/brave_search.rs にリトライが入る
- [ ] cargo test が通る
```

DoD は検証可能でも、命題未展開・範囲・失敗時・テストが無いので **スキップしない**。

### 後

```
## 背景
Brave API の一時的な 429/5xx でツール呼び出しが即失敗する。

## 目的
一時障害時に限って安全にリトライする。

## 実現内容
- 429/5xx/接続エラー時のリトライ（最大3回・指数バックオフ）
- 401/403 は即失敗
- リトライ判定をテスト可能な単位に置く

## 範囲
- やる: 429 / 5xx / 接続エラーのリトライ
- やらない: 401/403 のリトライ、無制限リトライ

## 完了条件
- [ ] 429 と 5xx と接続エラーのみリトライ（401/403 はしない）
- [ ] 最大3回・指数バックオフ
- [ ] リトライ判定は純関数（または同等）に切り出し、モックなしで 429/401 をユニット検証できる
- [ ] 呼び出し側は追加設定なしで既定のリトライが有効
- [ ] `cargo test` が通る

## 影響範囲
- 変更: src/brave_search.rs

## テスト範囲
- 429/5xx/接続エラーをリトライ: 自動 — `cargo test retry`（モックでリトライ経路）
- 401/403 はリトライしない: 自動 — 同上（リトライしない経路が1つ）
- 最大3回・指数バックオフ: 自動 — 同上（回数・間隔のアサーション）
- 判定の切り出し: 自動 — 同上（純関数または同等のユニット）
- `cargo test` 全体: 自動 — `cargo test`
```

（利用しやすさ＝既定で効く、メンテ／改造＝判定の切り出し。UIは非該当で省略）
