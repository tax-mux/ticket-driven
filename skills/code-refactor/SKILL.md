# コードリファクタリング

肥大化・深いネストを **実装中に予防**し、漏れは **実装直後に検討**する。

**常時読むのは本ファイルだけ。** 本文は目録の条件に合うファイルだけ開く。`sections/` をまとめて読まない。

## 目録

| 開く条件 | 読むファイル |
|----------|----------------|
| 実装中の予防手順 | `sections/prevent.md` |
| 実装直後の計測・分割・浅化・実施ルール | `sections/post.md` |
| 検討メモの出力テンプレ | `sections/template.md` |

## 概要

### 二段構え

| 段階 | 目的 |
|------|------|
| **実装中（予防）** | しきい値を超えるコードをそもそも書かない／押し上げない |
| **実装直後（セーフティネット）** | 触ったファイルだけ計測し、超過なら分割・浅化を検討 |

`ticket-driven` の日常フローでは両方を自動で行う（確認不要。実施は任意だが予防を優先）。

### しきい値（必須検討）

次を超えたら **必ず検討**する（無条件に実施するわけではない）。

1. **600行を超えるソースコードは、機能構成単位でファイル分割を検討する。**
2. **ネストが５つを超えるコードはネストを解いて階層を浅くすることを検討する。**

### トリガー

- チケット駆動の **実装ステップ**（予防を常時適用）
- ユーザーがリファクタ・分割・ネスト解消を依頼したとき
- レビュー・実装中に上記しきい値を超えた（超えそうな）コードを見つけたとき
- OpenCode / エージェントが保守性改善を提案するとき

関連: 日常フローは `ticket-driven`。差分は `git-diff`。大きすぎる作業分割は `ticket-split`。
