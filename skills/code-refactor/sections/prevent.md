# 実装中の予防（第一優先）

機能を足すときから次を守る。事後リファクタ前提の巨大差分を書かない。

1. **触る前に一瞥**: 対象ファイルの行数・ネストがしきい値近くなら、追記前に分割先／抽出先を決める
2. **増やさない書き方**
   - early return / guard clause
   - 長い分岐・ループ本体は関数に切り出す
   - 新規ロジックは既存ファイルを押し上げるより、責務が違うなら新ファイル＋薄い呼び出し
3. **超えそうならその場で小さく直す**: 今回の差分がしきい値超過を引き起こす／悪化させるなら、同チケット内で振る舞いを変えずに分割・浅化してよい
4. **混ぜない**: 仕様変更とリファクタは意図が分かる単位に分ける（同一チケットでも論理ブロックを分ける）

ジャーナルは通常不要。予防で大きめの分割をしたときだけ `リファクタ: 予防 — {要約}`。
