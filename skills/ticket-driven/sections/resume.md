# 再開（途中停止・モデル切替・別セッション再開）

途中で止まったチケット／セッションを再開するとき用。  
**把握したらすぐ実装に入らない。** 現状把握の直後にサイズ判定→分割／再分割を挟む。

## いつ開くか

- 「#N 再開」「途中から続けて」「実装状況を把握して再開」
- セッション停止・モデル変更のあと、同じ親票で作業を続けるとき
- ユーザーが子チケット検討を許している／分割が怪しいとき

## 必須順（スキップ禁止）

```
1. 現状把握（まだコード変更しない）
   - 取得 Tier（`ops.md`）:
     - 既定: Tier 3（journals / children）— 分割証拠・着手履歴・監査が要る再開
     - 委任パック＋description で DoD・検証・依存が足りる → Tier 1 に降格可
     - 子の特定だけ → Tier 2。MemPalace 要約があれば先に読み、Redmine は不足分だけ
   - 未完 DoD・途中差分・前回の失敗点を1短くまとめる
2. サイズ判定（残り作業）
   - 未完 DoD 数、独立に検証できる塊、残りファイル／検証の広さ
   - ticket-split の必須トリガ A–F（DoD≥4 / 独立塊≥2 / 中心成果≥2 / 中心パス≥4 / 同居禁止 等。事前指標のみ）に当たるか
3. 分割／再分割（実装より先）
   - 必須トリガ or 1セッションで Resolved 不能 → ticket-split（子作成 or 粗い子の再分割）
   - 単一の小残りのみ → `分割不要:` を親に残してよい（フォーマットは journal.md）
   - 再開時点で分割証拠が古い／親のまま実装していた → 必ず再判定（「もう分割済」で飛ばさない）
4. 作業単位を決める
   - 子がある／今回切った → **細かい未完了の子だけ**着手（親 In Progress 禁止）
   - 分割不要の単一票のみ → その票で着手
5. セッション境界（推奨）
   - 可能なら **新セッション**で子に着手（同一スレでのモデル差し替えは避ける）
   - モデルは子単位で固定する
6. 子（または分割不要票）で通常フロー
   - 着手ノート → 実装 → 検証 → Resolved（after-split / 日常フロー）
```

## 禁止

- 現状把握の直後に edit/write へ入ること
- 厚い親・粗い子のまま「続きの実装」に入ること
- 再開だからといって分割判定・分割証拠ノートを省略すること
- 同一セッション内でモデルを差し替えて太いコンテキストのまま続行すること（止めたら境界で切り直す）

## 再開ジャーナル（推奨）

把握とサイズ判定のあと、親または作業子に1行:

```
再開検討: 残りDoD={n} / 判定={分割|#子…|分割不要} / 作業単位=#{id}
```

その後、分割した場合は通常の `分割:`、着手時は子に `着手: …`。
