# 再開（途中停止・モデル切替・別セッション再開）

絡まった依頼の **続き** でも、入口だけ追加する。**出口（着手〜完了）は日常フローと同じ。**

## 前提

- チケットは **指示書ではない**。自分（または前セッション）が書いた **計画と作業ログの正本**
- 再開のたびにゼロから組み直す必要は **ない**
- 作業ログ（ジャーナル）+ 差分 + 未完 DoD を読み、**計画がまだ有効か** を判定する

## 禁止（再開でも）

- チャット履歴・圧縮サマリ・セッション内メモを計画代わりにすること
- ジャーナルを読まずに edit へ入ること
- 「続きの実装」でサイズ判定・分割証拠を飛ばすこと

## 必須順

```
A. 現状把握（edit 禁止）
   - 対象チケット get（Tier は ops.md。ジャーナル必須）
   - ジャーナル全文: 分割 / 着手 / 完了 / 再開検討 / 失敗メモ
   - git diff・ビルド/テストの現状（詰まり点を1行）
   - セッションや圧縮サマリは参考程度。計画の根拠にしない

B. リプラン要否（ここが再開の分岐）
   次を **すべて** 満たす → 計画有効（リプラン省略可）:
   - 作業単位 #{id} がジャーナルで明示されている（着手 or 再開検討）
   - 委任パック6項目が当該票のジャーナルに実在
   - 未完 DoD が description と矛盾しない
   - 差分が「その作業単位の範囲内」または未着手
   - 必須トリガ A–F に **新たに** 該当していない（ticket-split policy）

   1つでも欠ける → リプラン必要（C へ）
   すべて満たす → D へ（計画継続）

C. リプラン（計画を書き直す — まだ edit しない）
   - ticket-refine（description / DoD を現状に合わせる）
   - ticket-split（分割・再分割・分割不要ノート）
   - 親または作業子に `リプラン: {理由1行}` → journal.md
   - 作業単位 #{id} を確定

D. 計画継続 or リプラン完了
   - ジャーナルに `再開検討:` 1行（journal.md 形式）
   - 計画継続のみのとき `計画継続: 作業単位=#{id} / 根拠={ジャーナル上の着手or再開検討}` も可
   - 可能なら **新セッション**（圧縮済み・モデル切替・長時間停止後は推奨）

E. 以降は日常フロー（SKILL.md と同じ）
   - 着手ノート未記載なら `着手:` + 委任パック + In Progress
   - 既に In Progress で委任パックあり → 実装〜完了へ
   - テスト → クローズ監査 → 完了 → Resolved
```

## 再開検討ジャーナル（B の直後に必ず1行）

```
再開検討: リプラン={要|不要} / 残りDoD={n} / 作業単位=#{id} / 根拠={計画有効の理由|リプラン理由}
```

`リプラン=不要` でも **省略禁止**（「続きやる」だけは不可）。

## 典型パターン

| 状況 | 判定 |
|------|------|
| 着手済み・DoD 半分・差分が範囲内 | リプラン不要 → 実装続行 |
| 前回スコープ外のファイルを編集していた | リプラン必要 → 分割 or 委任パック修正 |
| 親だけ In Progress・子に着手なし | リプラン必要 → 作業単位を子に切る |
| 圧縮サマリとジャーナルが矛盾 | ジャーナル正。**新セッション + リプラン検討** |
| ビルドが壊れたまま放置 | リプラン必要。DoD に baseline 復旧を足すか別子に |

## 関連

- ジャーナル形式: `journal.md`
- 取得 Tier: `ops.md`
- 分割トリガ: `ticket-split` / `policy.md`
