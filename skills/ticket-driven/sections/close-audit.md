# クローズ監査（Resolved 前必須）

`status_id` を Resolved（または同等の完了）にする **直前**に実施する。未充足なら完了ノートも Resolved も出さない。

## 監査項目（すべて yes 必須）

| # | 項目 | yes の条件 |
|---|------|------------|
| 1 | DoD 全 `[x]` | description の完了条件がすべてチェック済み（未チェックが1つでもあれば no） |
| 2 | 検証一致 | 実行した検証が、当該票のテスト範囲・委任パックの「検証」と対応する |
| 3 | 親実装なし | 子がある親に実装差分・親 In Progress・親だけの「完了」で逃げていない |
| 4 | 範囲内 | 変更が影響範囲／委任パックの中心に収まる。DoD 外の追加成果を勝手に含めていない |
| 5 | 調査のみでない | DoD が現象解消／テスト pass なのに、調査メモだけで Resolved・新規戻ししていない。失敗アサーションを弱体化して「通った」扱いしていない |
| 6 | ステータス実体 | **完了ノートだけでは不足**。Resolved にする直前／直後の `get` で `status` が解決(3)（または同等の完了）であることを確認。終了(5)への遷移はエージェント通常経路では no |
| 7 | done_ratio 実体 | 進捗を扱う票では、解決前または同時に意図した `done_ratio`（多くは 100）が入っていることを `get` で確認。解決後に rate だけ直そうとして失敗したままなら no |

UI 変更がある場合は、既存の `ui-verify.md`（スクショ等）も満たすこと。

## 完了ノート形式

```
完了: {概要} — テスト: {結果}
クローズ監査: DoD全[x]=yes / 検証一致=yes / 親実装なし=yes / 範囲内=yes / 調査のみでない=yes / ステータス実体=yes / done_ratio実体=yes
```

どれか1つでも `no` → **Resolved 禁止**。不足を直すか、範囲外は別票へ切る。

## 親ハブの Resolved

全子が Resolved のあとだけ。親のクローズ監査は次を見る:

- 子がすべて Resolved
- 親 description の完了条件を子で充足した旨が追跡できる（`done_ratio` 100 または完了ノートで子 ID 列挙）。親も **Open 中に rate を入れてから** 解決(3)
- 親に実装を載せていない
