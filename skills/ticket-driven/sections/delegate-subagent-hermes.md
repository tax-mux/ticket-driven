# サブエージェント委任 — Hermes

共通ポリシーは `delegate-subagent.md`。本ファイルは **呼び出し口だけ**。

## 計画の正本

- **チケットのジャーナル + description** が計画。圧縮サマリ・長いセッション履歴は正本にしない
- 再開・委任前: `resume.md` — ジャーナルを読み **リプラン要否** を判定してから `delegate_task`
- 委任 `context` には **委任パック全文**（チケットに書いた計画）を載せる。チャット要約だけ渡さない

## ツール

- 委任: **`delegate_task`**（toolset `delegation`）
- 子は親履歴を見ない。**`goal` と `context` に委任パック全文を入れる**

## 直列（必須）

- **1 回の `delegate_task` = 子 1 枚**（単一 `goal`）
- `tasks=[...]` による **並列バッチは禁止**（ローカル LLM 1 プロセス前提）
- 前の委任が終わるまで次を呼ばない
- Kanban swarm の並列 worker も、子チケット実装には使わない

## 呼び出し例

```text
delegate_task(
  goal="#456 を Resolved まで完走（親 #100 には触らない）",
  context="""
委任パック:
- 作業単位: #456
- DoD: （子 description / ジャーナルの委任パックをそのまま）
- 影響範囲: …
- 検証: …
- 依存: …
- 禁止: 親実装 / 他子侵食 / 並列委任 / 追加の delegate_task

手順:
1. redmine_issues get #456（Tier 1。include なし）
2. 委任パックに従い実装・テスト
3. クローズ監査後、完了ノート + Resolved
4. 親・他子は更新しない（done_ratio は親セッション側）
"""
)
```

## 注意

- `context` が薄いと子は失敗する。委任パックの省略禁止
- `delegation.model` が安いモデルでも、DoD・検証は省略しない
- 失敗・タイムアウト時は共通ポリシーの **新セッション** フォールバック
- 親は要約を受けたら次の未完了子を **1 枚だけ** 選んで繰り返す
- TUI の `/agents`（`/tasks`）で委任状態を確認してよい
