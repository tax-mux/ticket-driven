# いつ重い手順を使うか（自動判定）

| 条件 | 動作 |
|------|------|
| 要件不足、命題未展開、品質観点未反映、分割候補未記載、または完了条件が検証不能 | **自動で** `ticket-refine`（確認不要。充足済みなら更新スキップ。詳細は目録で必要な節だけ） |
| 精緻化済、または充足済み（更新スキップ） | **自動で** `ticket-split` を **必ず開いて** 二段判定。必須トリガ A–F／機能構成または子の合格ライン割れで2つ以上なら **子を作成**し親に `分割:` ノート。分割不要なら親に `分割不要:` ノート（**省略禁止**） |
| すでに子があるが粗すぎる（1セッションで Resolved 不能） | **再分割**する（`ticket-split` の再分割）。細かい子を作業単位にする |
| すでに子がありセッション完走サイズ | 再分割しない。未完了の子を作業単位にする → `after-split.md`。親に実装着手しない。OpenCode/Hermes なら `delegate-subagent.md`（**子は直列のみ・並列禁止**） |
| 子を複数サブエージェントで同時起動しようとしている | **禁止**（ローカル LLM 1 プロセス）。1 枚ずつ。詳細は `delegate-subagent.md` |
| 分割証拠（`分割:` / `分割不要:`）が親ジャーナルに無い | **着手禁止**。先に `ticket-split` を完了させる |
| **再開**（途中停止・モデル切替・「状況把握して再開」） | **edit 禁止。** ジャーナルで **リプラン要否** を判定（`resume.md`）。不要なら計画継続→共通ステップ B へ。必要なら refine/split で計画を書き直してから B へ。Redmine get は `ops.md` の **取得 Tier** |
| 再開時に計画無効・必須トリガ新該当・親のまま実装していた | **リプラン必須**（「分割済だから大丈夫」で飛ばさない） |
| 依存の明示が必要 | `ticket-relation`（`precedes` / `blocks` 等） |
| テスト範囲が無い／曖昧／DoD の言い換えだけ | **自動で** 既存のテスト範囲を直す → `test-plan.md` |
| UI・画面・見た目の変更 | **Playwright**＋スクショ添付 → `ui-verify.md` |
| 実装中 | **リファクタ意識** → `refactor.md` |
| 実装完了後 | **必ず** テスト実行し DoD 検証 → **クローズ監査**（`close-audit.md`）→ 充足してから Resolved（UI なら添付済み） |
| クローズ監査が no の項目あり | **Resolved 禁止**。不足を直すか別票へ |
| DoD がテスト pass／現象解消なのに調査メモだけで止めようとしている | **Resolved / 新規戻し禁止**。修正するか解決子を切る → `bug-flow.md` / `close-audit.md` |
| 失敗 E2E／ユニットのアサーションを消す・弱めて回避しようとしている | **禁止**。ログ追加は可。修正かテスト誤りの証明 → `test-plan.md` |
| DOM／セレクタ欠落を FW マウント失敗と決めつけている | **禁止**。先にルート→View→テンプレの props／条件を trace → `bug-flow.md`、INIT_BOOTSTRAP §1.4 |
| 着手ノートに委任パックが無い | **実装禁止**。先に `delegate-pack.md` 形式で着手ノートを書く |
| 実装で触ったファイルが 600行超 or ネスト5超 | **自動で** `code-refactor` 事後検討 → `refactor.md` |

判定は毎回行う。充足済みなら **更新だけ**スキップしてよい。**分割判定と分割証拠ノートはスキップしない**（1セッションで収まる単一まとまりでも `分割不要:` を残す）。再開では **リプラン要否** を必ず判定する（毎回フル replan ではない）。
