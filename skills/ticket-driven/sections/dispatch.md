# いつ重い手順を使うか（自動判定）

| 条件 | 動作 |
|------|------|
| 要件不足、命題未展開、品質観点未反映、または完了条件が検証不能 | **自動で** `ticket-refine`（確認不要。充足済みなら更新スキップ。詳細は目録で必要な節だけ） |
| 精緻化済、または充足済み（更新スキップ） | **自動で** `ticket-split` を二段判定。機能構成またはセッション上限で2つ以上なら **子を作成してから**作業（確認不要） |
| すでに子があるが粗すぎる（1セッションで Resolved 不能） | **再分割**する（`ticket-split` の再分割）。細かい子を作業単位にする |
| すでに子がありセッション完走サイズ | 再分割しない。未完了の子を作業単位にする → `after-split.md` |
| 依存の明示が必要 | `ticket-relation`（`precedes` / `blocks` 等） |
| テスト範囲が無い／曖昧／DoD の言い換えだけ | **自動で** 既存のテスト範囲を直す → `test-plan.md` |
| UI・画面・見た目の変更 | **Playwright**＋スクショ添付 → `ui-verify.md` |
| 実装中 | **リファクタ意識** → `refactor.md` |
| 実装完了後 | **必ず** テスト実行し DoD 検証してから Resolved（UI なら添付済み） |
| 実装で触ったファイルが 600行超 or ネスト5超 | **自動で** `code-refactor` 事後検討 → `refactor.md` |

判定は毎回行う。充足済みなら **更新だけ**スキップしてよい。**分割判定はスキップしない**（1セッションで収まる単一まとまりなら「分割不要」と判定して進む）。
