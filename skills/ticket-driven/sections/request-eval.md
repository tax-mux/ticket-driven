# 評価エージェントへの依頼（別途定義時）

実装側が **自分で `評価:` を書いて完結しない**ためのフック。ホスト固有の叩き方は公開本文に書かず、ローカルスキル／ルールに委譲する。

## いつ有効か（検知）

次の **いずれか**があれば「別途評価エージェントが定義されている」とみなす:

| 検知 | 例 |
|------|-----|
| ホストスキル名が `ticket-driven-ask-*-eval` | pi の `ticket-driven-ask-cursor-eval` |
| ルール／スキル本文に「評価は別エージェントへ連絡」と明示 | Cursor 個人の対向スキル、ハーネス固有補足 |

**別途とみなさないもの:**

- `ticket-evaluate` スキルがカタログにあるだけ（同一セッション自己実行の入口）
- チャット上の「後で評価して」だけの宣言

未定義なら本フックは **スキップ**し、従来どおり同一セッションで `ticket-evaluate` を実行してよい（別視点推奨は残す）。

## タイミング（定義時は必須）

| # | いつ | 依頼種別 | 実装側の義務 |
|---|------|----------|--------------|
| 1 | create→refine→**split 完了直後**（親に `分割:` / `分割不要:` を書いた直後） | **計画** | `評価依頼: 計画` を対象票へ書き、ホスト手順で評価側へ連絡し **結果を待つ**。不合格なら **着手禁止**（refine/split やり直し） |
| 2 | **レビュー提出直後**（`status_id`=レビュー） | **実装** | `評価依頼: 実装` を実装票へ書き、ホスト手順で連絡し **結果を待つ**。自分で `評価:` を書かない |

計画依頼の対象票: 分割したなら **親**（子 ID をノートに列挙してよい）。分割不要ならその単一票。  
実装依頼の対象票: **実装チケット**（子があるなら子）。

## ジャーナル書式

```
評価依頼: 計画 — #{親または単一票} — 先方:{ホストが使う識別名} — 子: #a,#b（任意）
```

```
評価依頼: 実装 — #{実装票} — 先方:{識別名}
```

連絡に失敗したら:

```
評価依頼失敗: {計画|実装} — #{id} — {理由1行}
```

**禁止:** 失敗時に自己 `評価: 合格` でクローズへ進む。ユーザーへ短く報告し、再連絡または人手評価を待つ。

## 評価側の応答

- 計画・実装とも `ticket-evaluate`（notes のみ `評価:`）。status / done_ratio は触らない
- 計画評価の詳細は `ticket-evaluate`（種別: 計画）
- 実装評価の詳細は従来どおり（種別: 実装、原則レビュー状態）

## 定義時の禁止

- 実装した自分が `評価: 合格` / `条件付き合格` を書いて自己完結する
- 計画評価を待たずに着手する（不合格のまま着手する）
- レビュー未提出のまま実装評価だけ頼んで Resolved する

## ホスト委譲

公開スキルは「連絡せよ」まで。具体コマンド（例: `agent -p`、別セッション起動）は **載せるな**。マシン／ハーネスのローカルスキルが正本。
