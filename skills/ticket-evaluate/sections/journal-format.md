# 評価ジャーナル書式

Redmine `notes` に書く。チャット専用の評価で終わらせない。

## 必須プレフィックス

先頭行:

```
評価: {総合判定} — {1行要約}
```

直後に種別行（必須）:

```
種別: {計画|実装}
```

総合判定は `合格` / `条件付き合格` / `不合格` のいずれか。

## 本文テンプレ（実装）

```
評価: {合格|条件付き合格|不合格} — {1行要約}

種別: 実装

DoD:
- [達成|部分|未達] {完了条件1の要約} — 根拠: {パス/テスト/挙動}
- [達成|部分|未達] {完了条件2の要約} — 根拠: ...
- [達成|部分|未達] {完了条件3の要約} — 根拠: ...

検証: {実行したコマンドまたは「未実行: 理由」}

UI（画面があるとき）:
- 添付確認: {あり: ファイル名… | 対象票・関連とも空}
- トンマナ: {問題なし | 注意 — 内容 | 判定不可（証拠なし）}
- ユーザビリティ: {問題なし | 注意 — 内容 | 判定不可（証拠なし）}
- 根拠: {スクショ添付名 / Playwright / （証拠なし→不合格時はその旨）}
- ※ 添付空かつ `UI証拠なし:` 無し → 不合格。`UI証拠なし:` あり・理由具体 → 条件付き合格候補（満額合格にしない）

品質（注意点レーン / criteria Q1–Q5）:
- {特記なし | 所見を短く。合格判定の主軸にしない}
- Q5（類似・重複）: {なし | 既存 {パス} と類似。差分理由あり／なし}
- ブロッカー級なら「注意点（ブロッカー）」へ移す（失敗オープン署名等。漏洩はセキュリティ側）

セキュリティ（注意点レーン / criteria S1–S5）:
- {特記なし | 所見を短く。合格判定の主軸にしない}
- ブロッカー級なら「注意点（ブロッカー）」へ移す（認証バイパス・任意実行・秘密の本番漏洩等）

注意点（非ブロッカー）:
1. {内容}
2. {内容}

注意点（ブロッカー）:
- なし
（または列挙）

次: {任意。例: #1500 で合流消費 / 秘密鍵の失敗クローズを別票}
```

## 本文テンプレ（計画）

```
評価: {合格|条件付き合格|不合格} — {1行要約}

種別: 計画

計画:
- [達成|部分|未達] 命題の展開 — 根拠: …
- [達成|部分|未達] DoD 検証可能性 — 根拠: …
- [達成|部分|未達] 範囲・失敗時・テスト — 根拠: …
- [達成|部分|未達] 分割証拠（分割: / 分割不要:）— 根拠: …
- [達成|部分|未達] 子の切れ方（該当時）— 根拠: …

検証: チケット get のみ（コード差分なしで可）

注意点（ブロッカー）:
- なし

次: {合格なら着手可 / 不合格なら着手禁止・refine/split}
```

## ルール

- **status / done_ratio を変えない**（本ノートは評価専用。合格でも Resolved にしない）
- **`種別: 計画|実装` を必ず含める**
- **実装**: 原則 **レビュー** 状態の票に書く（本環境目安 status_id=7）。不合格なら「次:」で **差し戻し（レビュー→進行中）**（評価側は status を付けない）。親ハブへ書かない（実装票へ）
- **計画**: New / 未着手でも可。親ハブへ書いてよい。不合格なら「次:」で **着手禁止**
- 根拠のない「問題なさそう」禁止。パス・テスト名・分岐条件（計画なら journal 行・DoD 文言）を残す
- 既存の `完了:` ノートと矛盾する場合は、その差分を注意点に書く（完了ノートを消さない・上書きしない）
- 同じ票へ短時間で同内容を連投しない。追評価するときは「再評価:」と差分だけでも可

## 再評価

```
再評価: {合格|条件付き合格|不合格} — {前回からの差分1行}
...
```

## 最小例（短い票）

```
評価: 合格 — 代行完了時メール2種＋合流トークン。DoD3項目達成。

種別: 実装

DoD:
- [達成] ユーザー／控メール — sendDelegatedRegistrationMails + mail-send
- [達成] 期限付きトークン — delegated-merge-token（期限切れ null）
- [達成] 自己申込不変 — boundSalesCompanyId ガード + apply-account PASS

検証: bun test test/lib/delegated-*.test.ts / apply-account.test.ts — 全 PASS

UI: 対象外（API／メールのみ）

品質:
- Q1: ペッパー未設定時の固定文字列フォールバック（失敗オープン）→ 注意点へ
- Q3: 改ざんテストが末尾1文字置換でフレークし得る
- Q5: activationToken（保存前提）とは別契約の自己完結トークン — 差分理由あり。平行コピペではない

注意点（非ブロッカー）:
1. serverSecret がペッパー未設定時に固定文字列へフォールバック
2. 代理店控＝操作者宛（マスタにメール列なし）

注意点（ブロッカー）:
- なし

次: #1500 で ?merge= 消費
```
