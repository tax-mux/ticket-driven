# チケット評価 (Ticket Evaluate)

チケットを正本に、**計画（分割直後）**または**実装差分**を点検し、**評価を Redmine `journals`（`notes`）へ追記**する。

**常時読むのは本ファイルだけ。** 本文は目録の条件に合うファイルだけ開く。`sections/` をまとめて読まない。

## 種別（最初に分岐）

| 種別 | いつ | 見るもの |
|------|------|----------|
| **計画** | `評価依頼: 計画` のあと、または「#N の計画・分割を評価して」 | description の命題・DoD・範囲・テスト・分割証拠（`分割:` / `分割不要:`）・子の切れ方。**コード差分は必須にしない** |
| **実装** | `評価依頼: 実装` のあと、または「#N を評価して」（既定） | DoD と実装差分・テスト。原則 **レビュー** 状態 |

依頼文やジャーナルに種別が無ければ、票が未着手／New で実装パスが無い → **計画**、それ以外 → **実装**。

## 位置づけ

| 対比 | 違い |
|------|------|
| 本スキル | **点検・評価**。チャット報告で終わらせず、必ず対象票に `評価:` ノートを書く（`種別: 計画\|実装`） |
| `close-audit.md`（ticket-driven） | **実装者が Resolved 直前に自己監査**する手順。評価スキルの代替ではない |
| `git-diff` | diff 観点の補助。チケット DoD 照合・ジャーナル追記は本スキル |
| `request-eval.md`（ticket-driven） | 実装側が別途評価エージェントへ **連絡**するフック。本スキルは評価側の実行手順 |

## ステータスとの関係（必須）

- **実装評価**: 原則、票の status が **レビュー**（本環境目安 id=7。`redmine_metadata` で確認）のときに評価する
- **計画評価**: New / 未着手でも可。status は変えない
- **進行中のまま解決**する経路は ticket-driven で禁止。実装評価もその前提に合わせる
- **`評価:` は `notes` のみ**。`status_id` / `done_ratio` / `estimated_hours` は **触らない**（合格でも自分で Resolved にしない）
- **実装・不合格**: ノートに不合格と差し戻し指示。実装側が **レビュー→進行中** に戻す（評価側は status 変更禁止）
- **計画・不合格**: ノートに指摘。実装側は **着手禁止**（refine/split やり直し）
- **合格 / 条件付き合格（ブロッカーなし）**: 実装側が進む（計画なら着手可、実装ならクローズ監査→解決）
- 「フィードバック」status は人の差し戻し用。LLM 評価には使わない
- Resolved 済み票の再評価は従来どおり可（プロセス注意として書いてよい）

## HARD GATE との関係

- **コード変更・コミット・PR はしない**（読み取り＋必要ならテスト実行＋ Redmine `notes` のみ）
- 評価の結果として修正が必要でも、**勝手に直さない**。指摘をジャーナルに残し、修正はユーザー指示または別セッションの `ticket-driven` 着手で行う
- `status_id` / `done_ratio` / `estimated_hours` は **触らない**（評価は状態を動かさない）
- **実装評価**を親ハブに書かない（実装票へ）。**計画評価**は親（または分割不要の単一票）へ書いてよい

## 概要（最短）

1. `redmine_issues` **get** `#N`（`include: ["journals","children","relations","attachments"]`）
2. **種別を決める**（計画 / 実装）
3. **計画**: DoD・範囲・検証可能性・分割証拠・子の切れ方を点検（コード差分不要）→ `評価:`（`種別: 計画`）
4. **実装**: 完了条件・範囲・着手／完了ジャーナルから実装パスを特定。**画面票は先に attachments**。ソース・テストを読み実行 → `評価:`（`種別: 実装`）
5. ユーザーへ要約を返し、ジャーナル追記済みであることを明示

**画面票（実装評価）:** DoD／テスト範囲に画面到達・手動 UI があるのにチケット上の画面証拠が無い → 原則 **不合格**。例外はジャーナルに `UI証拠なし: {理由} — 代替: …` があり理由が具体的なときのみ（多くは条件付き合格。満額合格にしない）。

起動例: `#N 評価して` / `#N の計画を評価して` / `#N 実装を点検して` / `#N の実装をレビューして（評価）`

MCP: **`mcp-redmine_redmine_issues`** `action: "update"` + `notes` のみ（`ticket-update` に逃がして status を変えない）。
