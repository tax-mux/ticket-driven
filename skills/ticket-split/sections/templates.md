# 子チケット作成テンプレート

充足項目は種別共通。空欄のまま作らない。合格ラインは `ticket-refine`。

## 共通（Feature / Task の本文）

```
## 背景
（親から、このセッション単位に必要な1〜3文）

## 目的
（この子で達成すること）

## 範囲
- やる: （この子だけ）
- やらない: （親の他の子、またはこの子の外）

## 完了条件
- [ ] （この子で検証可能な条件。目安1〜3個）

## 影響範囲
- 変更: path/to/file

## テスト範囲
- 完了条件1: 自動 — {コマンド}（見るもの）
- 完了条件2: 手動または目視 — …
- 失敗経路: （この子の範囲に失敗時があるときだけ）

## 使うスキル（任意）
- {スキル名}（必要なら節）: {この子で必要な理由1行}
```

### 使うスキル欄の書き方

子を委任された側が親を見なくても、条件付きで必要なスキルに気付けるようにする欄。

- **書く**: この子の範囲・完了条件・影響範囲から、開く必要が読み取れるスキルや節だけ
- **書かない**: 毎回の流れで開くもの（`ticket-driven` / `ticket-update` 等）。ただし条件付きの節（`ticket-driven` の `ui-verify.md` 等）は書いてよい
- **書かない**: `skills/navigation-protocol.md` の索引に無いスキル（ホスト固有のローカルスキル等）
- 各行に **理由1行**。名前だけ並べない
- 該当が無ければ **節ごと省略**（空欄や「なし」で残さない）

例:

```
## 使うスキル（任意）
- code-refactor: 変更先 src/server/routes.ts が 600 行超
- git-pr: 完了条件に PR 作成を含む
- ticket-driven の ui-verify.md: 一覧画面の表示を変えるためスクショ添付が要る
```

## Bug（修正系。共通に足す）

共通のうえに、再現・期待・実際を残す（親からこの不具合ぶんを切る）。範囲・影響範囲・テスト範囲は共通テンプレを使う。

```
## 再現手順
1. …

## 期待値
…

## 実際
…
```

回帰はテスト範囲に、完了条件との対応で書く（「回帰テスト」チェックだけにしない）。

## Task（作業系）

共通テンプレを使う。手順が必要なら「範囲」の下に書く。**テスト範囲を省略しない。**
