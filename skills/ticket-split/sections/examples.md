# 分割例

### 親チケット: "ユーザー管理機能の実装"

親は精緻化済み。第1段で「モデル／API／一覧／詳細」に分け、第2段でセッション完走まで切る:

```
#{CHILD_A} User モデル・バリデーション
  依存: なし
  範囲: モデル定義と必須バリデーション。永続化実装は #{CHILD_B}
  完了条件: 必須欠落でバリデーション失敗、充足で成功
  テスト範囲: 自動 — 成功1・失敗1

#{CHILD_B} users 永続化
  依存: #{CHILD_A}
  範囲: 保存・取得。API/画面は他の子
  完了条件: 保存と ID 取得ができる
  テスト範囲: 自動 — 保存往復1

#{CHILD_C} GET ユーザー一覧 API
  依存: #{CHILD_B}
  範囲: GET 一覧のみ。POST/PATCH/DELETE は別子
  完了条件: 契約どおり一覧を返す
  テスト範囲: 自動 — 200 と空一覧

#{CHILD_D} POST ユーザー作成 API
  依存: #{CHILD_B}
  範囲: POST のみ
  完了条件: 作成成功。失敗時は検証エラーを返す
  テスト範囲: 自動 — 成功1。失敗経路: 自動 — 必須欠落

#{CHILD_E} ユーザー一覧の表示
  依存: #{CHILD_C}
  範囲: 一覧表示のみ。検索・ページネは #{CHILD_F}
  完了条件: 一覧が表示される
  テスト範囲: 手動 — 件数表示。目視 — 空一覧

#{CHILD_F} ユーザー一覧の検索・ページネーション
  依存: #{CHILD_E}
  範囲: 検索とページ送りのみ
  完了条件: 検索で絞れ、ページを送れる
  テスト範囲: 手動 — 検索とページ送り
```

「CRUD API 1枚」「一覧画面 1枚」で止めない。検証が独立した機能構成になるときだけ検証用の子を切る。親の `cargo test` を検証子へ丸投げしない。
