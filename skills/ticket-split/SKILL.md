# チケット分割 (Ticket Splitting)

親チケットを子チケットに分割し、作業を細分化する。

## 目的

- 大きなチケットを独立して実装可能な単位に分解
- 並列作業を可能にする
- 進捗管理を細かくする
- 各タスクの完了条件を明確にする

## 分割方針

### 分割の基準

- **機能単位**: 独立した機能ごとに分割
- **階層単位**: フロントエンド / バックエンド / DB ごとに分割
- **ファイル単位**: 影響範囲が明確なファイルごとに分割
- **ステップ単位**: 実装ステップが明確な場合に分割

### 分割しない場合

- 1回のコミットで完結する小さな変更
- 依存関係が強く独立して実装できない場合
- 1時間未満で完了するタスク

## ワークフロー

### 1. 分割計画

親チケットの内容を分析し、分割案を策定:

```
## 分割案

### 子チケット1: {タイトル}
- 内容: ...
- 依存: なし（先行）
- 推定工数: ...

### 子チケット2: {タイトル}
- 内容: ...
- 依存: 子チケット1
- 推定工数: ...
```

### 2. 子チケット作成

```json
{
  "action": "create",
  "issue": {
    "project_id": "{プロジェクトID}",
    "parent_issue_id": 42,
    "tracker_id": 2,
    "subject": "{タイトル}",
    "description": "{説明}",
    "priority_id": 2
  }
}
```
ツール: `redmine_issues`

### 3. 関連付け

子チケット同士・親チケットとの関連を確認:

```json
{
  "action": "create",
  "issue_id": "{ID}",
  "relation": {
    "issue_to_id": 43,
    "relation_type": "relates"
  }
}
```
ツール: `redmine_issue_relations`

### 4. 親チケット更新

分割内容を親チケットのジャーナルに記録:

```json
{
  "action": "add_note",
  "issue_id": "{親ID}",
  "notes": "チケットを分割:\n- #{子1ID}: {タイトル1}\n- #{子2ID}: {タイトル2}"
}
```

### 5. 親チケットの進捗

子チケットの完了率に応じて進捗率を更新:

```json
{
  "action": "update",
  "issue_id": "{親ID}",
  "issue": { "done_ratio": 33 }
}
```

## 子チケット作成テンプレート

### Bug（修正系）

```
## 修正内容
{バグの説明}

## 修正方針
{どのように修正するか}

## 完了条件
- [ ] {具体的な検証条件}

## 影響確認
- [ ] 関連箇所の動作確認
- [ ] 回帰テスト
```

### Feature（実装系）

```
## 背景
{なぜ必要か}

## 実装内容
{具体的に何をするか}

## 実装詳細
### 変更ファイル
- {ファイルパス}: {変更内容}

### 新規ファイル
- {ファイルパス}: {用途}

## 完了条件
- [ ] {検証条件1}
- [ ] {検証条件2}

## テスト
- [ ] 単体テスト
- [ ] 結合テスト
```

### Task（作業系）

```
## 作業内容
{具体的な作業}

## 手順
1. {手順1}
2. {手順2}

## 完了条件
- [ ] {確認項目1}
- [ ] {確認項目2}
```

## 分割チェックリスト

- [ ] 各子チケットが独立して実装可能
- [ ] 依存関係が明確
- [ ] 各タスクの完了条件が具体
- [ ] 親チケットの範囲を網羅
- [ ] 重複がない
- [ ] 親チケットに分割記録あり

## 例

### 親チケット: "ユーザー管理機能の実装"

分割後:

```
#{101} ユーザーモデルの実装
  依存: なし（先行）
  内容: User モデルの作成、バリデーション、スコープ

#{102} ユーザーAPIの実装
  依存: #{101}
  内容: CRUD API の実装

#{103} ユーザー一覧画面の実装
  依存: #{102}
  内容: 一覧表示・検索・ページネーション

#{104} ユーザー詳細画面の実装
  依存: #{102}
  内容: 詳細表示・編集・削除

#{105} テスト実装
  依存: #{101}, #{102}, #{103}, #{104}
  内容: 全機能の単体・結合テスト
```
