# チケット分割 (Ticket Splitting)

親チケットを **機能構成 → セッション完走単位** の子チケットに分割し、作業を細分化する。

**常時読むのは本ファイルだけ。** 本文は目録の条件に合うファイルだけ開く。`sections/` をまとめて読まない。

## 目録

| 開く条件 | 読むファイル |
|----------|----------------|
| 二段判定・再分割・分割しない判断の詳細 | `sections/policy.md` |
| 障害・エラー（現象確認→調査→解決） | `sections/policy.md`（「障害・エラー修正の分割」） |
| 子を実際に作る／関連付け／親ノートを書く | `sections/workflow.md` |
| 子の description テンプレが必要 | `sections/templates.md` |
| 分割の具体例が欲しい | `sections/examples.md` |

分割不要と判定して戻るときも **`分割不要:` ノートは必須**。policy の機械的必須に当たるなら「不要」で戻ってはならない（`policy.md` を開く）。

## 自動起動（ticket-driven から）

`ticket-driven` で精緻化が済んだ、または要件充足済み（更新スキップ）と判定された直後に、**ユーザー確認なしで本スキルを実行**する。チャット上の判定だけで戻らない。

1. 親を `get` し、既存の子の有無を確認する
2. **機械的必須トリガ A–F** を先に見る（DoD≥4 / 独立塊≥2 / 中心成果≥2 / 中心パス≥4 / 同居禁止 等）— 当たれば分割必須。詳細は `policy.md`（事前に数えられる指標のみ。壁時計予言は使わない）
3. **二段**で分割案を作る（機能構成 → 子の合格ライン）— `policy.md`
4. 分割するなら子を作成する。**本文は親の切り出し**（プレースホルダ禁止）。依存を `ticket-relation` で付け、親に **`分割:` ジャーナル（必須）** — `workflow.md` / `templates.md`
5. 分割しないなら親に **`分割不要:` ジャーナル（省略禁止・理由フォーマット必須）** — `workflow.md`
6. 呼び出し元へ戻し、**子があるなら子だけ**を作業単位にする（親への実装着手禁止）

すでに子があり、いずれもセッション完走サイズなら新規作成せず、親に分割済みである旨が無ければ `分割:` 相当の列挙ノートを残して戻る。  
子が粗すぎる（1セッションで Resolved まで届かなさそう）→ **再分割する**（`policy.md`）。

## 目的

- 与えられたチケットを、実装可能な **機能構成** に分解する
- 各子は **エージェント1セッションで着手〜検証〜Resolved まで完走できる** 大きさにする（子の合格ライン＝事前指標。特定ハーネス名には依存しない）
- 各子は親の充足本文を **切り出した作業単位** であり、作成時点で `ticket-refine` と同じ充足ラインを満たす
- 親は範囲のハブ（進捗・最終 Resolved）に留める

## 概要: 二段分割

| 段 | 軸 | 役割 |
|----|-----|------|
| 1 | **機能構成** | 親の範囲を能力境界で切る |
| 2 | **セッション完走** | 各片が1エージェントセッションで Resolved まで届くか。子の合格ライン（事前指標）で超えるなら切る |

第2段を省略しない。子の本文は親の切り出し（プレースホルダ禁止）。詳細・再分割・分割しない場合は `policy.md`。

## 分割チェックリスト（要約）

- [ ] 必須トリガ A–F を事前指標だけで判定した（壁時計・ハーネス名は使わない）
- [ ] 第1段が機能構成単位（層・ファイル優先になっていない）
- [ ] 第2段で各子が合格ライン（DoD 1〜3・中心1・検証1系統・同居なし）
- [ ] 各子が独自の検証可能な完了条件（目安1〜3）と refine 充足ラインを満たす
- [ ] 各子のテスト範囲が子の完了条件に対応（親のコピーではない）
- [ ] 依存が明確（必要なら relation）／親に `分割:` または `分割不要:` ／作業は細かい子で着手

詳細判定は `policy.md`。作成手順は `workflow.md`。
