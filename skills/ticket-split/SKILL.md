# チケット分割 (Ticket Splitting)

親チケットを **機能構成 → セッション完走単位** の子チケットに分割し、作業を細分化する。

**常時読むのは本ファイルだけ。** 本文は目録の条件に合うファイルだけ開く。`sections/` をまとめて読まない。

## 目録

| 開く条件 | 読むファイル |
|----------|----------------|
| 二段判定・再分割・分割しない判断の詳細 | `sections/policy.md` |
| 子を実際に作る／関連付け／親ノートを書く | `sections/workflow.md` |
| 子の description テンプレが必要 | `sections/templates.md` |
| 分割の具体例が欲しい | `sections/examples.md` |

分割不要と判定して戻るだけなら、追加ファイルはゼロでよい（概要の判定で足りるとき）。

## 自動起動（ticket-driven から）

`ticket-driven` で精緻化が済んだ、または要件充足済み（更新スキップ）と判定された直後に、**ユーザー確認なしで本スキルを実行**する。

1. 親を `get` し、既存の子の有無を確認する
2. **二段**で分割案を作る（機能構成 → セッション完走上限）— 詳細は `policy.md`
3. 分割するなら子を作成する。**本文は親の切り出し**（プレースホルダ禁止）。依存を `ticket-relation` で付け、親に分割ジャーナルを書く — `workflow.md` / `templates.md`
4. 呼び出し元へ戻し、**子チケットを作業単位**として実装へ進む（許可待ちしない）

すでに子があり、いずれもセッション完走サイズなら作成せず「分割不要」と判定して戻る。  
子が粗すぎる（1セッションで Resolved まで届かなさそう）→ **再分割する**（`policy.md`）。

## 目的

- 与えられたチケットを、実装可能な **機能構成** に分解する
- 各子は **エージェント1セッションで着手〜検証〜Resolved まで完走できる** 大きさにする（Hermes / OpenCode のへたり防止）
- 各子は親の充足本文を **切り出した作業単位** であり、作成時点で `ticket-refine` と同じ充足ラインを満たす
- 親は範囲のハブ（進捗・最終 Resolved）に留める

## 概要: 二段分割

| 段 | 軸 | 役割 |
|----|-----|------|
| 1 | **機能構成** | 親の範囲を能力境界で切る |
| 2 | **セッション完走** | 各片が1エージェントセッションで Resolved まで届くか。超えそうならさらに切る |

第2段を省略しない。子の本文は親の切り出し（プレースホルダ禁止）。詳細・再分割・分割しない場合は `policy.md`。

## 分割チェックリスト（要約）

- [ ] 第1段が機能構成単位（層・ファイル優先になっていない）
- [ ] 第2段で各子がセッション完走サイズ
- [ ] 各子が独自の検証可能な完了条件（目安1〜3）と refine 充足ラインを満たす
- [ ] 各子のテスト範囲が子の完了条件に対応（親のコピーではない）
- [ ] 依存が明確（必要なら relation）／親に分割記録／作業は細かい子で着手

詳細判定は `policy.md`。作成手順は `workflow.md`。
